# B 站视频水印的原理，以及本工具的去水印策略

> 结论先放前面：**B 站网页/APP 里看到的"水印"没有一个是播放器叠加上去的**，
> 也没有任何一个可以靠接口参数关掉。要么在片源像素里，要么根本不可见。
> 所以去水印只能用「像素级修复」，而绝大多数番剧/影视本来就没有可见水印 —— 默认不该重编码。

## 一、实测：水印不在接口，也不在播放器层

| 验证项 | 做法 | 结果 |
|---|---|---|
| playurl 有没有水印开关 | 扫描 PGC（ep693247）与 UGC（同集官方投稿）两份 playurl 返回，匹配 `watermark/logo/brand/mark/stamp/sign` | **0 个字段**；`dyeid` 为空、`is_drm=false` |
| 播放器是不是 DOM 叠加 | headless Edge 打开视频页，查 `[class*=watermark]`、`canvas`、`video.src` | 水印节点 **0 个**，canvas **0 个**，`video.src` 是 `blob:`（MSE 流） |
| 同源内容有没有额外叠加 | 同一集分别走 PGC 与 UGC 两条链路取流，抽 3 帧比对 | 四角 edge/centre 比值、PSNR **完全相同** → 同一个源文件，UGC 侧没加压任何东西 |

三条叠加起来说明：**水印不是一层可关闭的东西，它已经和画面像素焊在一起了**。

## 二、那画面上的水印是哪来的

1. **片源自带**
   UP 主在剪映/PR/录屏软件里叠的台标、字幕条、"某某字幕组"，随视频一起上传。
2. **投稿时勾选的「我的水印」**
   B 站创作中心里的选项（可填昵称/ID）。开启后是**转码期烧进右下角**的，
   位置固定、大小随分辨率缩放 —— 这就是为什么它在 playurl 里查不到：它已经不是"图层"，而是像素。
3. **防盗录跑马灯**
   少数抢先看/影视/直播回放会在转码时叠加随观看者、时间变化的浮层（通常还在移动）。
   这类用固定矩形无效，必须按时间给 x/y 表达式。
4. **不可见溯源水印**
   频域/时域嵌入的 ID 水印（`dyeid` 就是这条链路的痕迹），肉眼不可见、不影响观看，
   任何画面处理都去不掉，也不用管。

所以「去水印」实际处理的是 1、2 两类（静态、位置固定），3 类需要动态参数，4 类无解但不影响观看。

## 三、五种处理方式的实测画质代价

测试方法：960×540 测试图 + 烧一个 `BILIBILI` 文字水印（带半透明黑底框），
分别用五种滤镜处理后与**无水印原图**比 PSNR（越高越接近原画）。

| 方式 | 滤镜 | 全局 PSNR | 水印框内 PSNR | 说明 |
|---|---|---|---|---|
| 不处理 | — | 31.19 | 16.60 | 基准：水印还在 |
| **插值 delogo** | `delogo` | **35.28** | **21.47** | 画质最好；细节纹理处会有一小块平滑痕迹 |
| 遮罩 removelogo | `removelogo`+mask | 34.16 | 20.08 | 形状任意的水印用它；要自备 mask 图 |
| 局部模糊 | `crop+gblur+overlay` | 33.33 | 19.09 | 半透明大字/大面积时观感更自然，不出色块 |
| 裁边 | `crop` | 43.12\* | 区域内无损 | \*与原片裁切版对比；代价是画面被裁掉一条、构图变化 |
| 马赛克 | `crop+scale+overlay` | 29.44 | 14.80 | 比不处理还低：破坏了原像素，只在"只要看不清"时用 |

## 四、工具里的策略（按原理调整后的行为）

- **默认关闭**：番剧/影视多数没有可见水印，保持 `-c copy` 无损封装（最快、不损失画质、HDR 不变）；
- 打开后按形态选模式：
  - 小块静态 logo / 台标 → `delogo`（默认，画质最好）
  - 半透明或大块文字水印 → `blur`
  - 需要"明确遮盖"而不在乎还原 → `mosaic`
  - 水印贴着画面边缘、且能接受裁掉一条 → `crop`（区域内零损失）
  - 形状不规则（手写签名、图形 logo） → `mask` + 自备遮罩图
- **多区域**：`x:y:w:h;x:y:w:h`，用于"台标 + UP 主水印"同时存在的片子（转成滤镜链串联）；
- **时段**：`0-30` 只处理前 30 秒（片头 logo），生成 `:enable='between(t,0,30)'`；
- **编码跟随源**：1080P 及以下用 `libx264 -crf 18 -preset veryfast`；
  4K 或源本身是 HEVC 时自动切 `libx265 -crf 21 -tag:v hvc1`，避免 4K 用 h264 体积爆炸；
- **代价**：除 `crop` 外都要重编码，速度大约等于"下载时间的 1/3～1/2"，且 HDR 会转 SDR。

## 五、遮罩图怎么做

白色 = 要抹掉的像素，尺寸必须和视频分辨率一致（B 站 1080P 就是 1920×1080）。

```bash
# 画一个白块当遮罩（对应右下角一块 300x90 的区域）
ffmpeg -f lavfi -i color=c=black:s=1920x1080:d=1 \
  -vf "drawbox=x=1580:y=950:w=300:h=90:color=white:t=fill" -frames:v 1 mask.png
```

放到容器的 `/config` 目录下，页面「遮罩图」填 `mask.png`（或在 CLI 用 `--delogo-mask /config/mask.png`）。
想要贴合形状，就从视频里抽一帧到 PS/画图里把水印涂成白色、其余涂黑。

## 六、动态水印（跑马灯）怎么处理

固定矩形无效，得让坐标随时间走。用「原始滤镜」透传（CLI）：

```bash
python bili_pgc_dl.py ep123456 --delogo-raw \
  "delogo=x='if(lt(t,60),20+t*6,380)':y=24:w=300:h=90:show=0"
```

`x` 支持表达式，先抽帧测出水印在 t=0 与 t=60 的坐标，再定斜率；不同片源路径不一样，需要自己标定。

## 七、已知局限

- `delogo` 在大面积、纯色背景上会留下明显的"糊块"；纯色背景建议 `blur` 或 `crop`；
- 字幕烧在画面里（硬字幕）时，去水印区域可能压到字幕，建议先抽帧确认坐标；
- 10bit/HDR 片源重编码后是 8bit SDR，色彩会变（工具会提示）；
- 跑马灯需要手工标定，工具只提供 `--delogo-raw` 这个逃生口。
